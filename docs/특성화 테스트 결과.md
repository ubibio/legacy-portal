# 특성화 테스트 결과 - processApproval 커버리지와 안 덮인 분기

> **이 문서는 무엇을·왜 보는가**
> 특성화 테스트는 리팩토링의 안전망인데, 안전망에 **구멍(테스트가 지나가지 않는 분기)** 이 있으면 그 경로의 동작이 바뀌어도 테스트는 초록색 그대로다. 커버리지는 "테스트가 코드의 어디를 실제로 지나갔는가"를 재는 지표다.
> 이 문서는 `processApproval` 과 추출된 4개 메서드의 커버리지를 기록하고, **아직 고정되지 않은 분기**를 목록으로 남겨 다음 리팩토링(R06 enum · R09 도메인 이동) 전에 무엇을 더 고정해야 하는지 정하는 근거로 삼는다.

- 측정 시점: 커밋 `137c2d8` (processApproval 메서드 추출 직후)
- 테스트: `src/test/java/kr/hull/portal/approval/ApprovalServiceTest.java` 6개 - 전부 통과
- 측정 도구: JaCoCo 0.8.12 (`mvnw verify` → `target/site/jacoco/jacoco.xml`), SonarQube 26.6 에도 같은 값 반영

`statusLabel` · `amountGrade` · `myDrafts` · `myInbox` 와 `NoticeService` · `ScheduleService` 는 이번 6개 테스트의 범위 밖이라 0%다.

### 분기는 지나가지만 "검증"하지 않는 것

커버리지는 코드가 **실행됐는지**만 잰다. 아래는 실행은 되지만 테스트가 결과를 확인하지 않는다.

| 대상 | 현재 상태 | 위험 |
|---|---|---|
| 메일 수신자 · 제목 · 본문 (`[결재요청]` · `[결재승인]` · `[결재반려]`) | 실행만 됨 | 리팩토링 R03(메일 공통화)에서 문구가 바뀌어도 테스트가 모른다 |
| 감사로그 문자열 (`APPROVAL SUBMIT/APPROVE/REJECT/CANCEL id=.. by=..`) | 실행만 됨 | R02(로그 공통화)에서 형식이 바뀌어도 모른다 |
| `updatedAt` 갱신 / 무시될 때 안 바뀜 | 확인 안 함 | R09(엔티티로 이동)에서 갱신이 빠져도 모른다 |
