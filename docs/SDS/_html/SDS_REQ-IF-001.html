진행현황테스트중 (비고: 소스 역추출.)
요약결재(상신·승인·반려)·긴급공지 알림 메일을 MailSender 인터페이스 뒤에서 발송한다. 제목·본문 양식은 MailFormat 한 곳에서 만들고, 현재 구현체 ConsoleMailSender 가 콘솔에 === MAIL === 블록으로 출력한다. 업무 서비스는 구현체를 모른다(DIP).

2. 근거

SRS 없음 (엑셀 F열 · 소스만으로 분석). 아래는 요구사항정의서 F열(상세내용) 원문이다.

[개요]
결재 · 공지 알림 메일을 MailSender 인터페이스 뒤에서 발송하여, 실제 발송 수단을 바꿔도 업무 코드가 바뀌지 않게 한다.

[상세 기능 요구사항]
1) MailSender.send(받는 주소, 제목, 본문) 하나로 발송한다.
2) 제목 형식은 '[{태그}] {문서 제목}' 이다. 태그: 결재요청 · 결재승인 · 결재반려 · 긴급공지.
3) 본문 형식은 '안녕하세요 {이름}님,\n{안내 문구}\n제목: {문서 제목}' 이며 필요 시 줄을 덧붙인다.
4) 현재 구현체 ConsoleMailSender 는 콘솔에 '=== MAIL ===' 블록으로 출력한다.
5) 받는 사람이 DB 에 없으면 발송하지 않는다.

[입력 / 출력]
- 입력: 받는 주소, 제목, 본문
- 출력: 메일 발송(현재 콘솔 출력)

[제약 조건 / 비기능 요구사항]
- 제목 · 본문 문자열을 한 글자도 바꾸지 않는다(ApprovalNotificationOutputTest 가 출력 비교).
- SMTP 등 실제 발송 구현체를 추가할 때 업무 서비스 코드를 고치지 않는다.

[검증 기준]
- 결재 상신 시 콘솔 출력의 TO 가 결재자 이메일, SUBJECT 가 '[결재요청] {제목}' 이다.
- MailSender 를 대체 구현으로 바꿔 끼워도 기존 테스트가 통과한다.
