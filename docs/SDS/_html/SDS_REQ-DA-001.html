@DataJpaTest
class CodeValuePersistenceTest {
    @Autowired
    private NoticeRepository noticeRepository;
    @Autowired
    private JdbcTemplate jdbcTemplate;
    @Autowired
    private EntityManager entityManager;

    @Test
    void 공지_상태와_분류는_DB에_정수_그대로_저장된다() {
        Notice notice = noticeRepository.save(Notice.draft("점검", "본문", 2, 1L, false, LocalDateTime.of(2026, 10, 17, 9, 0)));
        notice.setStatus(9);
        entityManager.flush();

        Map<String, Object> storedRow = jdbcTemplate.queryForMap(
                "select status, category from notice where id = ?", notice.getId());
        assertThat(storedRow.get("STATUS")).isEqualTo(9);
        assertThat(storedRow.get("CATEGORY")).isEqualTo(2);
    }
}

REQ-DA-003 으로 enum 전환할 때 위 테스트가 '전환 전후 컬럼 값 동일'의 안전망이 된다. 따라서 전환 전에 먼저 만들어 둔다.

10. 검토 의견 · 후속 과제

보존 대상

  • DB 저장값: 결재 status 0/1/2/3/9, type 1~4, priority 1~3, 공지 status 0/1/9 · category 1/2/3, 일정 status 0/1/9, 사용자 role 1~3
  • API 정수 code: action 1/2/3/9, 응답 status · type · priority · role 정수
  • public getStatus() int 반환 · setStatus(int) 시그니처 (특성화 테스트 계약)
  • 정의 밖 action 조용히 무시

개선 대상 (차후)

  • type · priority · 공지 status · category · 일정 status · role 의 enum 전환과 범위 밖 값 거절 - REQ-DA-003 (+ REQ-NF-003 입력 검증)
  • 나머지 코드 컬럼에 대한 JDBC 직접 조회 특성화 테스트 부재 - 전환 전 추가 권장
  • 응답 JSON 정수 형식은 value(0) 비교로 간접 고정 - jsonPath("$.status").isNumber() 로 명시 권장(새 테스트로 추가, 기존 테스트 본문은 수정하지 않음)

연계 요구사항: REQ-DA-003(나머지 코드 enum 전환), REQ-NF-001(API 계약 보존), REQ-NF-003(입력 검증).
