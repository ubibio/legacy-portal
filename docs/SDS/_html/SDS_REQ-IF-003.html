                .andExpect(jsonPath("$.category").value(2));

    void 사원이_게시_API를_호출하면_200과_빈_본문이고_상태는_0이다() throws Exception {
        String responseJson = mockMvc.perform(post("/api/notices")

        long noticeId = ((Number) JsonPath.read(responseJson, "$.id")).longValue();

        mockMvc.perform(post("/api/notices/" + noticeId + "/publish")
                        .contentType(MediaType.APPLICATION_JSON).content("{\"userId\":1}"))
                .andExpect(status().isOk())
                .andExpect(content().string(""));

                .andExpect(jsonPath("$[?(@.id == " + noticeId + ")].status").value(0));

10. 검토 의견 · 후속 과제

보존 대상

  • 기존 NoticeService · ScheduleService public 시그니처와 업무 규칙(게시 권한 팀장 이상, 겹침 경계 '미만', 확정은 소유자만)
  • 감사로그 문구 NOTICE CREATE · NOTICE PUBLISH · SCHEDULE CREATE · SCHEDULE CONFIRM 과 형식 [AUDIT] [yyyy-MM-dd HH:mm:ss] 동작 id=.. by=..
  • 긴급공지 메일 제목 [긴급공지] {제목} · 본문 양식(MailFormat), 메일 후 감사로그 순서
  • 조용한 무시 · null 반환, 소유자 null 확정 시 NullPointerException
  • DB 저장값 status 0/1/9 · category 1/2/3 정수

개선 대상 (차후 재설계)

  • 조용한 무시 · null 반환 → 사유 있는 오류 응답(404/403/409/400) - REQ-NF-002
  • 필수 필드 누락 시 500 → 400 + 필드별 사유 - REQ-NF-003
  • 본문 userId 신뢰 → 로그인 사용자 - REQ-SE-002
  • 공지 status · category, 일정 status 를 enum 으로 (DB 정수 유지) - REQ-DA-003
  • 범위 밖: UserController 가 User 엔티티를 직접 반환(UserController.java:23-25) - 같은 DTO 원칙 적용 검토

검토 의견

F열의 목록 · 내 일정 조회는 '기존 서비스 그대로 호출' 조건과 달리 서비스에 해당 메서드가 없다. 업무 규칙이 없는 단순 조회이므로 서비스에 읽기 메서드(findAll · ownedBy)를 추가하는 것으로 해석하며, 이는 기존 동작을 바꾸지 않는다. 일정 등록 거부 시 응답은 결재 process 와 맞춰 200 + 빈 본문으로 두고, 오류 응답 전환은 REQ-NF-002 에서 한 번에 바꾼다.

연계 요구사항: REQ-NF-002(명시적 오류), REQ-NF-003(입력 검증), REQ-SE-002(요청자 신원), REQ-DA-003(코드 enum), REQ-NF-001(결재 API 계약 - 같은 DTO 방식).
