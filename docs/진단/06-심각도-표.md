# 06. 스멜 심각도 종합표

> **이 문서는 무엇을·왜 보는가**
> 스멜은 한꺼번에 다 고칠 수 없으므로, **영향이 크고·넓게 퍼져 있고·다른 개선의 전제가 되는 것부터** 처리해야 한다. 이 문서는 01~05 진단에서 찾은 스멜을 같은 기준으로 점수화해 **심각도순으로 줄 세우고**, 그 순서를 실제 리팩토링 작업 순서로 바꾸는 근거로 삼는다.
> 스멜별 상세 설명과 ID 정의는 종합 목록 [docs/smells.md](../smells.md)를 기준으로 한다.

- 기준 시점: 커밋 `7d68470` (main)
- 근거 문서: [01 구조](01-구조-파악.md) · [02 중복](02-중복-코드.md) · [03 긴 메서드](03-긴-메서드.md) · [04 매직넘버](04-매직넘버.md) · [05 강결합](05-강결합.md)

## 평가 기준

| 항목 | 3점 | 2점 | 1점 |
|---|---|---|---|
| **영향도** - 고치지 않으면 무엇이 어려운가 | 변경 시 버그 위험·테스트 불가 | 읽기·수정이 느려짐 | 가독성 저하 수준 |
| **범위** - 얼마나 퍼져 있나 | 3개 서비스 이상 또는 10곳 이상 | 2개 서비스 또는 4~9곳 | 1곳~3곳 |
| **선행성** - 다른 개선의 전제인가 | 이걸 먼저 안 하면 다른 리팩토링이 위험 | 일부 개선과 함께 해야 효과 | 독립적으로 처리 가능 |

**점수 = 영향도 + 범위 + 선행성** (3~9) → 🔴 높음 8~9 · 🟠 중간 6~7 · 🟡 낮음 3~5

같은 점수 안에서는 **선행성이 높은 것을 위로** 두었다. 🟡 구간(13~18)은 독립적으로 처리 가능해 순서보다는 관련 작업 때 함께 처리한다.

### 상위 스멜을 높게 본 이유

- **S01 테스트 부재**: 그 자체로 버그는 아니지만, 이게 해결되지 않으면 **나머지 모든 리팩토링이 "동작 보존"을 증명할 수 없다.** 그래서 1순위.
- **S04 매직넘버**: 가장 넓게 퍼져 있고(45곳), `processApproval` 분기 정리·권한 판정 이동·라벨 중복 제거가 모두 enum을 전제로 한다.
- **S03 · S02**: 결재 업무의 핵심 경로라 변경이 잦고, 복잡도 25짜리 메서드는 수정할 때마다 놓치는 분기가 생길 위험이 크다.
- **S06 · S05**: 동작을 전혀 바꾸지 않고 고칠 수 있는 **가장 안전한 첫 리팩토링**이면서, 고치고 나면 메일·로그를 테스트에서 검증할 수 있게 된다.

## 처리 순서 (심각도 → 실제 작업 단계)

| 단계 | 처리 스멜 | 작업 | 완료 기준 |
|:-:|---|---|---|
| 0 | S01 | **특성화 테스트 작성** - 결재 4개 전이(정상 + 조용히 무시), 공지 게시, 일정 생성·겹침·확정, 메일·로그 출력 | 테스트 green, 이후 단계 내내 본문 불변 |
| 1 | S06 · S05 · S07 | 메일·감사로그 인터페이스 추출 + 생성자 주입, 로그·메일 본문 조립 공통화 | 직접 `new` 0곳, 출력 문자열 동일 |
| 2 | S04 · S14 · S18 | 코드값 enum 도입(`ApprovalStatus` 등) + `@Convert`, 라벨을 enum으로, 금액 기준 상수화 | DB 정수값 동일, 테스트는 정수 리터럴 그대로 green |
| 3 | S03 · S10 · S11 | `processApproval` → `submit`/`approve`/`reject`/`cancel` 위임, 조기 반환, 의미 있는 이름 | 메서드 50줄·중첩 2 이하, public 시그니처 유지 |
| 4 | S09 · S08 · S02 | 상태 전이·권한·본인 판정을 엔티티/`UserRole`로 이동 | `ApprovalService` 는 조율만 |
| 5 | S12 · S13 | 요청/응답 DTO(record) 분리 | JSON 구조·필드 레거시와 동일 |
| 6 | S15 · S16 · S17 | 남은 정리 (조회 패턴, 변명 주석 제거, 필요 시 `Clock` 주입) | - |
| 이후 | S19 · S20 | **재설계 단계** - 조용한 실패를 예외/결과 응답으로, 설정 외부화 | 동작 변경이므로 리팩토링과 분리 |

> 각 단계는 **0단계 특성화 테스트가 그대로 green** 인 상태에서만 다음으로 넘어간다.
