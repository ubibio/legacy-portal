# 04. 매직넘버 진단 - 숫자에 숨은 의미 찾기

> **이 문서는 무엇을·왜 보는가**
> 매직넘버(Magic Number)는 `if (s == 1)`, `role >= 2` 처럼 **의미 설명 없이 코드에 박힌 숫자**다. 숫자만 보고는 "1이 상신인지 승인인지" 알 수 없어 주석·화면·DB를 뒤져야 하고, 같은 숫자가 여러 곳에 흩어져 있어 값이나 규칙이 바뀌면 빠짐없이 고치기 어렵다(원시 타입 집착, Primitive Obsession).
> 이 문서는 코드의 숫자를 모두 찾아 **의미를 추정·근거와 함께 기록**하고, 어떤 숫자를 enum·상수로 바꿀지 정하는 근거로 삼는다. 단, **DB에 저장되는 정수값 자체는 바꾸지 않는다**(enum을 써도 `@Convert`로 기존 숫자 그대로 저장).

- 기준 시점: 커밋 `7d68470` (main)
- 조사 대상: `src/main/java` 전체 + 같은 숫자 코드를 쓰는 화면 `src/main/resources/static/index.html`
- 이전 문서: [01-구조-파악](01-구조-파악.md) · [02-중복-코드](02-중복-코드.md) · [03-긴-메서드](03-긴-메서드.md)

## 추정 근거 표기

| 표기 | 뜻 |
|---|---|
| **코드주석** | 엔티티·서비스의 주석에 의미가 적혀 있음 (코드 자체는 숫자만 앎) |
| **화면** | `index.html`의 라벨·버튼 문구로 의미가 확인됨 |
| **용도추정** | 주석·화면 없이 쓰이는 위치와 전후 코드로 추정 |
| **⚠ 미사용** | 의미는 정의돼 있으나 그 값을 만들거나 판정하는 코드가 없음 |

| 9 | 취소 요청 | 코드주석 · 화면 | `:149` / 취소 버튼 `act(id,9)` `:142-143` |

- 값이 **"처리 후 도달할 상태 코드"와 일부러 맞춰져** 있다(1→상신, 2→승인, 3→반려, 9→취소). 용도추정: 구분값과 결과 상태를 같은 숫자로 두어 외우기 쉽게 한 설계. 그래도 **상태와 동작은 다른 개념**이라 enum은 분리하는 게 맞다.
- **API 계약값이다.** 화면과 외부 호출자가 `POST /api/approvals/{id}/process` 에 이 숫자를 직접 보낸다 → **요청 형식(정수)은 그대로 유지**하고 서버 내부에서만 enum으로 변환.
- 정의되지 않은 값(예: 4, 5)이 오면 어느 분기에도 안 걸려 **조용히 무시** - 보존 대상.

## 정리 - 보존 대상 vs 개선 대상

**보존 대상** (enum·상수로 바꿔도 그대로 둬야 하는 것)
- **DB 저장 정수값**: M1~M8의 모든 숫자. enum + `@Convert`(`AttributeConverter`)로 code를 매핑하며, `@Enumerated(STRING)`(문자 저장)·`@Enumerated(ORDINAL)`(순번 저장 - 9가 4로 어긋남) 금지
- **API로 주고받는 정수**: `type`, `priority`, `action` 요청값과 응답 JSON의 `status`·`type`·`priority`·`role` 숫자
- **정의되지 않은 값의 동작**: 모르는 `action`은 조용히 무시, 모르는 상태는 라벨 `알수없음`, 검증 없이 저장되는 `type`·`priority`
- **판정 결과**: `role >= 2` 권한 기준, 지출 100만원 이상 우선순위 상향, 금액 등급 경계값(이상/미만)

**개선 대상** (권장 순서)

| 순서 | 대상 | 기법 | 이유 |
|:-:|---|---|---|
| 1 | M1 `ApprovalStatus` · M2 `ApprovalAction` | enum + `@Convert`, 라벨 포함 | 등장 횟수 최다(20곳), `processApproval` 리팩토링([03](03-긴-메서드.md))의 전제 |
| 2 | M5 `UserRole` | enum + 권한 판정 메서드 | `>= 2` 서열 가정을 이름으로 드러냄, 3곳 중복([02](02-중복-코드.md) D3) 해소 |
| 3 | M9 · M10 | 이름 있는 상수(서로 분리) | 같은 값·다른 의미의 혼동 방지 |
| 4 | M6 `NoticeStatus` · M8 `ScheduleStatus` | enum + `@Convert` | `statusLabel` 중복([02](02-중복-코드.md) D5) 해소 |
| 5 | M3 · M4 · M7 | enum + `@Convert` | 서버 판정은 1곳씩이라 효과는 작지만 의미 일관성 확보 |

> ⚠ **미사용 값**(휴가·구매·기타 유형, 낮음·보통 우선순위, 공지 내림, 일정 취소 등)도 enum에 **빠짐없이 넣는다.** DB나 API에 이미 그 숫자가 들어올 수 있어서, 빠뜨리면 변환 단계에서 오류가 나 동작이 바뀐다.
> 이 작업 역시 **특성화 테스트로 현재 숫자 입출력을 먼저 고정**한 뒤 진행하며, 테스트는 enum이 아닌 **기존 정수 리터럴로 검증**한다.
